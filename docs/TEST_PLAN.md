# 测试计划与需求追踪（T002 设计）

**状态**：T003-A/B 与 T005 单范围下载已实施并运行自动化测试；Python CLI 续传、平板及其余真实设备/网络实验仍未运行。每个用例只有在对应阶段真正执行并保留证据后才能标为 PASS。

## 1. 执行原则

- 自动化用例使用 pytest、临时目录、合成内容和可注入的磁盘/时钟/网络故障；CI 不依赖真实手机、Wi-Fi、外部服务、密钥或付费 API（NFR-007）。
- 本机 TestClient、多进程或 loopback 测试只说明程序行为，不得作为手机/平板/真实 Wi-Fi 成功证据（ADR-003、NFR-009）。
- 文件用例必须验证 HTTP 状态、统一错误 `code`、磁盘可见对象、元数据、SHA-256 及临时文件清理；不可只断言“无异常”。
- 除现有 T001 测试外，下表均为 `DESIGNED / NOT_RUN`。实施任务完成后将用例 ID、命令、Git SHA、日志/实验原始数据路径写入 `docs/STATUS.md` 与 `docs/EXPERIMENTS.md`。

## 3. 测试数据与故障注入规范

| 类别 | 数据/方法 | 用途 |
| --- | --- | --- |
| 内容 | 0 B、1 B、1 KiB、跨缓冲区二进制、随机确定性字节、Unicode 名称、同名对象 | 内容、编码和碰撞覆盖 |
| 散列 | 测试中预先计算固定 SHA-256 | 验证服务端与客户端完整性 |
| 临时目录 | pytest `tmp_path` 下创建独立 `managed_root` | 不读取或写入用户真实文件 |
| 磁盘故障 | 存储适配器注入 `ENOSPC`、短写、原子移动失败 | 验证回滚，而非耗尽真实磁盘 |
| 网络故障 | 可控测试 transport/proxy 截断、超时或取消 | 验证任务失败、清理与 CLI 恢复 |
| 时间 | 可注入时钟 | 测试配对码、会话、临时文件和幂等键过期 |
| 并发 | asyncio/多进程屏障与固定小上限 | 验证资源槽位和状态隔离；不当作 Wi-Fi 实验 |
