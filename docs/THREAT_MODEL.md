# 局域网安全威胁模型（T002 设计）

**状态**：设计已完成，控制措施尚未实现。本文定义 T003 需要落实和验证的最低安全边界；它不把家庭 Wi-Fi、HTTP 或访问令牌描述为已获得的加密保护。

## 1. 信任边界与假设

| 实体/数据 | 信任级别 | 边界与前提 |
| --- | --- | --- |
| Windows 主机操作者与本机控制面 | 可信 | 选择受控根目录、显式启用 LAN、生成/展示配对码、查看脱敏状态 |
| 服务端 `managed_root` 与本地配置 | 受保护对象 | 仅服务进程和操作者可写；不是客户端可传路径 |
| 已配对的手机、平板、CLI | 有限信任 | 仅在会话、权限范围、配额和时效内访问；设备可能丢失或被恶意网页诱导 |
| 同一 Wi-Fi/热点的其他设备 | 默认不可信 | 不因处于同网段而获得文件或上传权限 |
| 浏览器/API 输入 | 不可信 | 包括文件名、multipart 内容、`file_id`、Range、分页、设备标签、Origin、请求头和所有 JSON 字段 |
| 互联网与公网 | 不在首版信任范围 | 默认不监听公网地址、不映射端口、不修改防火墙（FR-001、NFR-001） |

首版可在可信家庭 LAN 使用，但 LAN 不是机密信道。没有 TLS 的 HTTP 会以明文发送配对码、Cookie、Bearer token、文件名和文件内容；被动监听、ARP 欺骗或恶意 AP 仍可窃取会话或篡改流量。访问令牌只能限制未持有令牌的请求，**不能**防御同网段链路窃听或主动中间人。HTTPS 是后续 P2 受控升级项，不在 T002/T003 中虚构为已提供。

## 2. 推荐授权方案与替代方案

### 2.1 选择：短时一次性配对码 + 限时会话

1. 操作者在仅本机可见的控制面生成 6 位随机配对码，选择 `read` 或 `read_write`，有效期 10 分钟、使用一次即失效。
2. 设备向 `POST /api/pairings` 提交该码和 `client_kind`。服务端在来源地址与码两个维度限制为连续 5 次失败/10 分钟。
3. 浏览器成功后仅获得 `HttpOnly; SameSite=Strict; Path=/api` Cookie；CLI 成功后仅从响应体一次获得 256-bit Bearer token。服务端只存 token 摘要。
4. 会话绝对有效期 8 小时；操作者或设备可撤销；服务端验证撤销状态。默认不向会话续期。
5. QR 码（T004/P1）只能承载服务地址/端口，不能承载配对码、Cookie、token 或私有文件标识。

**为什么适合本项目**：它不需要账号、密码重置、第三方身份系统或付费服务；移动端输入一次短码即可获取同源 Cookie，CLI 可显式保存自己的令牌；失窃凭据的窗口有上限，操作者可撤销。它仍依赖操作者安全地传递配对码，且 HTTP 无法隐藏码或令牌。

### 2.2 替代方案比较

| 方案 | 优点 | 主要问题 | 结论 |
| --- | --- | --- | --- |
| 不认证，仅依赖家庭 Wi-Fi | 零实现复杂度 | 任意同网段设备可读写；不满足 FR-006 | 拒绝 |
| URL 中的共享 token | 复制链接方便 | 浏览器历史、代理、Referer、截图和日志容易泄露；难撤销 | 拒绝 |
| 长期用户名/密码 | 用户熟悉 | 需要注册、找回、存储/哈希、跨设备管理；仍无 HTTP 机密性 | 超出首版范围 |
| 短码 + 限时 Cookie/Bearer | 无账号、可撤销、适合浏览器和 CLI | 需限速、CSRF/Origin 处理，HTTP 仍可窃听 | **采用** |
| 客户端证书或 mTLS | 强设备身份 | 证书发放、安装、更新和移动端 UX 成本高 | 后续 HTTPS 调研，不用于 T003 |

## 3. 令牌、会话、浏览器与 CLI 细节

### 3.1 凭据保护

- 配对码和访问令牌用密码学安全随机源生成；令牌至少 256 bit。服务端记录 HMAC/哈希摘要而非明文 token。配对码是低熵值，必须结合短时、一次性和限速，不能只靠哈希保护。
- 禁止将秘密写入 URL、查询参数、路由路径、二维码、日志、异常消息、指标标签、截图样例或 Git。请求日志应脱敏 `Authorization`、`Cookie` 和 multipart 头。
- Cookie 会话只用于同源浏览器；未启用 HTTPS 时不能设置 `Secure`，因此需要在 UI 和文档中明确“可信 LAN 临时使用”，不要表示为私密连接。启用 HTTPS 后 cookie 必须加 `Secure`。
- CLI token 由用户的本地安全存储策略负责；首版 CLI 应限制文件权限、避免终端回显/日志和命令行参数泄露。T006 再实现客户端持久化细节。
- 会话撤销、过期和无效凭据都以统一的 `401`/通用错误反馈处理，避免泄露令牌是否曾存在。

### 3.2 浏览器 Origin、CORS 与 CSRF

- 浏览器 UI 将来必须与 API 同源。默认不配置允许任意来源的 CORS，尤其不能使用 `Access-Control-Allow-Origin: *` 加凭据。
- 对 Cookie 认证的所有状态变更（配对、上传、撤销），要求 JSON/multipart 的预期内容类型，验证 `Origin` 与当前服务 origin 精确相等；缺失或不匹配均拒绝 `403 origin_not_allowed`。这能阻止常见跨站表单/脚本滥用，但不是 HTTP 窃听防护。
- `SameSite=Strict` 降低跨站自动携带 Cookie 的概率；它不是唯一保护。跨站 JavaScript 无法设置 Bearer `Authorization` 且服务端不放开 CORS。
- CLI Bearer 请求不依赖 Origin；其 token 不应被浏览器脚本持有。浏览器要调用 API 时使用 Cookie，不把 token 放入 localStorage/sessionStorage。

## 4. 威胁与控制矩阵

| ID | 威胁/攻击路径 | 风险 | T003 控制措施 | 残余风险与验证 |
| --- | --- | --- | --- | --- |
| TM-01 | 未授权读取文件、枚举 `file_id` | 泄露私人文件 | 所有文件 API 先验会话与 `read` scope；未认证不查询对象；资源 ID 为 UUID | 已配对的读会话仍可读全部已发布文件；自动化拒绝测试 |
| TM-02 | 未授权上传或越权写入 | 磁盘污染/耗尽 | 上传要求 `read_write`，配对码由操作者选择 scope；未知/撤销会话拒绝 | 有写权设备仍可上传允许大小内容；权限与撤销测试 |
| TM-03 | `../`、绝对路径、盘符注入 | 任意文件读取/覆盖 | API 路径只接受 UUID；服务端生成 `storage_key`；从不拼接客户端路径 | 操作者错误配置根目录仍有风险；路径模糊测试 |
| TM-04 | 恶意文件名、同名、符号链接/reparse point | 路径逃逸、覆盖、响应头注入 | 展示名校验；重名不影响 UUID；`staging`/`objects` 仅服务端命名；拒绝链接/非常规文件并复查根内解析 | Windows 特殊 reparse 行为需实机测试；链接和 Unicode 测试 |
| TM-05 | 超大/无限上传 | 内存、磁盘、CPU 耗尽 | 流式写入+边界计数；单文件/总配额/保留空间；SHA-256 流式计算；`413/507` 后清理 | 内容哈希仍消耗 CPU；超限和 ENOSPC 注入测试 |
| TM-06 | 并发上传/下载淹没 | 文件句柄、磁盘、带宽耗尽 | 上传 2、下载 8 默认并发槽位；超时、限队列、任务状态 | 数值需真实 LAN 实验校准；本机并发压力测试 |
| TM-07 | token 泄露、长期有效或重放 | 未授权持久访问 | 256-bit token、服务端仅摘要、8 小时绝对 TTL、撤销、日志脱敏、短码一次性 | HTTP 监听者可实时窃取；过期/撤销/日志检查 |
| TM-08 | 恶意网站跨站上传/撤销 | CSRF、浏览器会话滥用 | 同源 UI、无宽松 CORS、SameSite Cookie、Cookie 状态变更强制 Origin | 老旧浏览器与 HTTP 环境需真实设备验证；Origin/CORS 自动化测试 |
| TM-09 | 文件变更后错误续传 | 内容拼接损坏 | 发布不可变快照；强 ETag 为 SHA-256；T005 `If-Range` 不匹配返回完整 `200`，CLI 隔离旧部分 | 后续版本替换策略需实施；Range/版本集成测试 |
| TM-10 | 上传中断留下 `.part` | 半成品暴露/磁盘泄漏 | 先写私有 staging；只在 hash/配额通过后原子发布；断开立即清理，启动/定时清理孤儿 | 进程崩溃时清理延后；中断/重启测试 |
| TM-11 | 服务意外公网暴露 | 外部攻击面 | 默认 `127.0.0.1`；LAN 需显式参数和实际地址提示；不做端口映射/防火墙更改 | 用户或路由器自行开放无法由应用完全阻止；启动配置人工检查 |
| TM-12 | 日志泄露 token、Cookie、绝对路径 | 二次泄露 | 结构化脱敏日志；只记录 `request_id`、短 ID、错误类别；禁记请求体和敏感头 | 第三方库访问日志需配置验证；日志审计测试 |
| TM-13 | 恶意上传内容 | 主机/其他用户受害 | 不执行、不预览、不自动解压；以下载附件方式返回；可选后续本地杀毒扫描 | 不提供防病毒保证；安全提示和手工验证 |
| TM-14 | HTTP 篡改/窃听、恶意 AP | 凭据和文件泄露/篡改 | 明确限制；仅可信 LAN 短时使用；SHA-256 可事后发现内容不一致 | 不能阻止实时窃听/篡改；HTTPS/mTLS 留作未来受控决策 |

## 5. 文件与磁盘安全执行规则

1. `managed_root` 必须是操作者的绝对路径配置；服务启动时创建/验证 `objects` 与 `staging`，拒绝相对根目录或不可访问路径。
2. 入站数据只流入随机 `staging/<uuid>.part`；文件名、MIME、size 声明都不可信。大小以实际读取字节计数，内容类型不作为安全许可。
3. 每次上传同时计算 SHA-256；客户端提供的 hash 仅可作为比对值，不能替代服务端计算。成功时在同一卷使用原子移动，并先完成数据/元数据顺序的一致性策略。
4. `storage_key`、`file_id`、临时名均由服务端生成；展示名仅元数据。下载时以固定对象名打开，进行“普通文件、根内、非链接”复查。
5. 发布快照后不原地修改。上传失败、超限、校验失败、断开和写入异常都不能生成 `FileRecord`；孤儿临时文件只按 staging 专用目录规则清理。
6. 用户可上传的内容不自动执行、解析或解压；日志不保存其内容和原始路径。

## 6. 已获得与未获得的保证

| 能通过本设计获得（实现并测试后） | 本设计不能承诺 |
| --- | --- |
| 默认拒绝未配对设备访问受保护 API | HTTP 链路机密性、抗被动监听或抗中间人 |
| 令牌不在 URL/日志/浏览器 JS 中暴露 | 已授权设备本身恶意或被盗后的内容保密 |
| 客户端路径不能决定服务器写入位置 | 恶意文件内容无害或已经过病毒扫描 |
| 临时上传不作为已发布文件暴露 | 所有 Windows reparse-point/race 情形在未实测前完全无漏洞 |
| 强 ETag/SHA-256 支持发现并防止错误续接 | 真实 LAN 性能、移动浏览器兼容性或公共网络安全 |

## 7. 实施前检查点

- T003 开始前确定配对码在本地控制面如何生成和显示、`managed_root` 如何由操作者配置，以及会话/元数据是否先采用 SQLite；这些属于实现选择，不可在没有记录的情况下临时扩展。
- 所有文件/会话/日志代码应先按 [API 契约](API_CONTRACT.md) 与 [测试计划](TEST_PLAN.md) 建测试，再实现处理路径。
- 引入 HTTPS、客户端证书、跨网段监听、远程管理或额外身份系统，需要新的 ADR 和用户批准。
