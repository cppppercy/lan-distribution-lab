# 软件需求规格说明书（SRS）

**项目**：LAN Distribution Lab — 面向局域网的可靠文件传输与多终端协同分发系统  
**版本**：1.0（需求基线，允许通过决策记录受控变更）  
**日期**：2026-11-08  
**状态**：需求已整理；功能未实现。  
**优先级**：P0 必需、P1 重要、P2 候选扩展。所有“通过”均需实际证据。

## 1. 依据、目的与边界

### 1.1 课程依据与项目定位
课程老师明确要求项目与网络通信有关、形成具有一定工作量的应用，选题不限、可用现有项目；老师倾向认真投入、功能完整的作品。老师没有公布具体评分权重、最低代码量、强制语言、强制 TCP+UDP 组合或精确截止日期。**本文件中的性能实验、工程规范和创新目标是团队自行制定的质量标准，不冒充老师的原话或官方评分细则。**

### 1.2 项目目标
在可信局域网中，以一台 Windows 电脑为中心节点，为手机、平板提供便捷的文件收发；以 Python CLI 作为确定性实验客户端，实现可靠的恢复传输和并发策略测试，并通过可复现实验解释设计效果与局限。

### 1.3 使用环境与资源
- 主机：Windows，32 GB 内存。测试客户端：手机、平板；补充若干电脑本机独立进程。
- 网络：家庭 Wi-Fi 优先，手机热点为备选。G0 用户已口头确认基本局域网连通性，正式实验仍须记录拓扑。
- 开发：ChatGPT 规划/审核，Codex 主执行，DSH 备用；GitHub `cppppercy/lan-distribution-lab` 是唯一共享版本来源。
- 费用：优先本地开发；按价值使用小额模型 API，云主机不是必备资源。
- 交付：可运行软件、测试记录、网络实验材料、可据实撰写的课程报告（最终报告可 Word 转 PDF）。

### 1.4 不在首版范围内
公网穿透、云同步、用户注册与长期身份体系、完整 BitTorrent 式 P2P、原生 iOS/Android 安装包、真正的无线多播文件载荷传输、跨网域高可用、复杂自适应拥塞算法、加密传输的无条件承诺。不得用“协同”暗示客户端互相传输数据块；首版指**中心节点统一协调多个接收端**。

## 2. 参与者与关键流程

**参与者**
- Host：运行服务器，管理被授权共享的文件、传输会话与访问策略。
- Browser Client：手机/平板浏览器，访问局域网页面、上传/下载并观察进度。
- CLI Client：专用 Python 客户端，进行分块、断点续传与可控实验。
- Operator：在可信局域网中启动/停止服务、授权设备与查看记录的本机用户。

**目标流程**
1. 主机启动服务，显式开启 LAN 监听，显示局域网地址/二维码（二维码为 P1）。
2. 客户端获得授权后，浏览或上传共享文件，发起下载。
3. 服务端检查权限、文件版本及请求范围，以流式方式返回数据并记录任务结果。
4. CLI 可在连接中断后核实同一个文件版本并续传、完成 SHA-256 校验。
5. 多客户端同时接收文件，服务端执行可切换分发策略，收集时间/流量/结果数据。

## 3. 功能需求（可追踪）

### 3.1 P0：基础可用闭环
- **FR-001 服务监听**：默认仅绑定 `127.0.0.1`；只有操作者显式选择 LAN 模式时绑定局域网接口，显示实际地址和端口；不自动开启路由器端口转发。
- **FR-002 健康与状态**：提供简单健康接口（计划 `GET /api/health`），区分进程存活与核心服务可用性，非敏感字段可公开。
- **FR-003 受控共享列表**：仅发布操作者明确选择的文件；记录稳定资源 ID、名称、大小、版本标识、SHA-256（完整性校验可异步计算但发布前必须有可靠最终结果）。
- **FR-004 基础下载**：经授权 GET 下载所选文件；浏览器普通下载可运行，响应不应一次将整个大文件装入内存。
- **FR-005 基础上传**：浏览器经授权向服务端上传文件；有限制大小/配额、临时文件、完成后原子确认，不得通过文件名写入任意路径。
- **FR-006 访问控制**：默认拒绝未经授权的文件列表、上传、下载；采用短时令牌或等效一次性配对方式；令牌不得写入日志、URL 查询参数或仓库。
- **FR-007 基本 UI**：移动端可打开页面，选择上传/下载，显示可理解的任务状态、结果与错误；不预设移动浏览器支持应用控制的持久文件续传。
- **FR-008 文件结果校验**：服务端保存上传文件的校验值；CLI 或验证工具能核对下载后 SHA-256 一致。空文件、Unicode 名称和重名冲突要有确定行为。
- **FR-009 失败处理**：网络不可达、权限无效、文件不存在、空间不足、取消请求等返回可诊断错误；不能把失败显示为成功。

### 3.2 P1：可靠性与多设备分发
- **FR-101 范围请求**：下载服务正确实现单一字节范围 `Range`，返回 `206` 与正确 `Content-Range`/`Content-Length`；不可满足范围返回 `416`；遵循 RFC 9110。首版允许明确拒绝多范围请求，不得静默返回错误字节。
- **FR-102 文件版本**：采用强校验标识或等效不可变版本 ID；支持 `If-Range` 或等效先验版本检查，资源变化时不得把不同版本的数据错误拼接。
- **FR-103 CLI 断点续传**：将未完成文件与元数据保存在安全的临时目录；启动时校验版本、当前偏移和目标路径；中断后只请求缺失部分；结束时校验大小及 SHA-256，成功后原子落盘；版本变更和校验失败必须重试/隔离，不可错误“完成”。
- **FR-104 并发任务**：至少两台真实客户端能同时请求同一共享文件；任务状态和结果互不混淆。
- **FR-105 策略对照**：支持顺序分发、普通并发、受控并发（固定并发上限作为首版），能明确复现实验设置；不假定受控策略总是更快。
- **FR-106 任务记录**：保存必要元数据（开始/结束时间、字节量、状态、错误类型、匿名客户端标识）；日志不记录秘密令牌或私人文件内容。
- **FR-107 可重复实验驱动**：CLI 可指定文件、并发数、迭代次数及输出路径；结果导出为结构化 CSV/JSON，并标明本机模拟与真实 Wi-Fi 测试的区别。
- **FR-108 桌面设备发现**：在安全边界清楚的前提下尝试 UDP 广播或组播发现，发现失败时提供手动 IP/二维码回退；不能依赖浏览器直接使用 UDP Socket。
- **FR-109 可选 UI 增强**：二维码连接、传输历史与明确的连接状态展示；以适配实际设备为验收依据。

### 3.3 P2：调研后再决定
上传断点续传、动态并发/速率调度、跨平台独立桌面程序、跨网段实验、HTTPS 设备配对、可信 P2P 文件块交换。实现 P2 前需新增技术决策及可验证收益假设。

## 4. 非功能性要求
- **NFR-001 安全默认值**：localhost 优先，LAN 监听需显式选择，未经授权不得读写共享数据；禁止开放公网作为默认行为。
- **NFR-002 数据保护**：限制共享根目录/路径解析，防止目录穿越与符号链接逃逸；上传使用临时文件和原子提交；不得覆盖无关文件。
- **NFR-003 资源有界**：对文件大小、上传总量、客户端并发、请求体、超时、队列与磁盘配额设定可配置上限；大文件用流处理。
- **NFR-004 可维护性**：分离 HTTP 适配层、传输业务逻辑、存储、调度与实验工具；接口/配置有类型或校验；文档和测试同步。
- **NFR-005 可观测性**：记录结构化且脱敏的错误、传输结果和性能指标；时间与字节量单位清晰；用户可停止服务。
- **NFR-006 可移植性**：开发和主要验收以 Windows 为主；不得未经测试声称 Linux/macOS/移动端完全兼容。
- **NFR-007 可复现性**：固定依赖或锁文件、提供启动说明和 pytest；CI 在无真实设备与付费外部服务条件下运行纯单元/HTTP 集成测试。
- **NFR-008 性能评价**：不预设绝对 MB/s 或“提升百分比”；以控制变量、重复实验、原始数据、环境信息和正确性为准。
- **NFR-009 真实性**：所有功能/测试/协议/性能陈述标注“设计中、已实现、已测试或未验证”，禁止把模拟客户端当作独立无线设备。

## 5. 技术架构基线（仍可在 G0/G1 内受控调整）
- Python 3.12+、FastAPI/Uvicorn、SQLite、pytest。
- Web：Vue 3 + TypeScript + Vite；以移动浏览器访问为基本形式。
- 传输：HTTP/1.1 over TCP；恢复下载遵循 Range 机制；完整性 SHA-256。
- 桌面发现：UDP 广播/组播（P1），手动 IP 作为可靠回退。
- CLI：Python 独立进程；用于确定性下载和对照实验。
- 不强制提前使用 Redis、Celery、容器编排、云数据库、云服务器。
- 接口契约先在 `docs/ARCHITECTURE.md` 设计，再按迭代实现；当前仅规划 `GET /api/health` 为首任务接口。

## 7. 测试与质量策略
- 单元测试：授权、文件名/路径、空文件、哈希、版本比较、字节范围边界、任务状态。
- 集成测试：临时目录与测试客户端、HTTP 200/206/416、失败/超时、不暴露未授权文件。
- 故障测试：断网/连接中断、版本变化、磁盘空间不足、重复提交、不完整临时文件。
- 性能实验：固定文件、网络环境、轮次、服务端资源；记录总完成时间、吞吐量、重传字节、失败率、公平性指标（定义须写入实验方案）。
- CI 使用可重复的虚拟测试替代真实设备；真实 Wi-Fi 实验单独手动执行。
